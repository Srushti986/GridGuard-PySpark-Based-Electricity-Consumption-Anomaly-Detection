## Real dataset

*Individual Household Electric Power Consumption* - UCI Machine Learning Repository
(https://archive.ics.uci.edu/dataset/235/individual+household+electric+power+consumption).
One household near Paris, one reading per minute, Dec 2006 - Nov 2010 (about 2.07 million rows,
about 1.25 % missing values written as `?`). The file has no meter or household IDs and no
anomaly labels; GridGuard does not invent any.

| Field | Meaning | Unit |
|---|---|---|
| `Date` | day, format `d/m/yyyy` | - |
| `Time` | time, format `HH:mm:ss` | - |
| `Global_active_power` | household minute-averaged active power - **primary metric** | kW |
| `Global_reactive_power` | household minute-averaged reactive power | kW |
| `Voltage` | minute-averaged voltage | V |
| `Global_intensity` | minute-averaged current intensity | A |
| `Sub_metering_1` | kitchen (dishwasher, oven, microwave) | Wh of active energy |
| `Sub_metering_2` | laundry room (washer, dryer, fridge, light) | Wh of active energy |
| `Sub_metering_3` | electric water heater and air conditioner | Wh of active energy |

The original file is never modified; cleaned results go to separate tables under `outputs/` (or HDFS).

## Synthetic sample - read this

`sample_electricity.csv` is **artificial** (generated by `tests/generate_sample_data.py`, fixed seed).
It contains deliberately injected problems for testing: `?` gaps, one negative reading, one
unparseable date, plus one high spike (9 Jan 2007, 03:00) and one low dip (10 Jan 2007, 19:00).
Anything detected in it says nothing about real households. Use it with
`python run_pipeline.py --sample`.
